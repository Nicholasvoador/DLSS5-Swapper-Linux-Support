# v2.2.9-linux.2 — RenoDX 8.5.0-rc10, and the panel that can drive it

The RenoDX add-on this fork installs moves from **6.5.3** to **8.5.0-rc10**, and the multipass build from **SF 26.0927.2125** to **SF 26.0928.0205**. Upstream 2.2.9 still ships 6.5.3, so the Linux build now fetches the newer add-ons itself.

## What changed

- **RenoDX 8.5.0-rc10 on Linux.** Upstream's 2.2.9 package carries 6.5.3, so the app now lays its own pinned add-ons over the payload. It downloads each release zip from RankFTW's rhi-repo, checks the zip's SHA-256, takes the one file out, and checks that file's SHA-256 too. Only then is each target replaced, each one whole. If you already have the payload, the app fetches only the add-ons (about 2 MB) and never downloads the 250 MB upstream package again.
- **The F8 panel's RenoDX bridge works with 8.5.0-rc10.** The panel drives RenoDX through RenoDX's own UI, at addresses pinned for each build. Two things went wrong with rc10:
  - **The addresses.** The rc10 pin is derived from the code itself: the `GetImGuiFunctionTable(19250)` store and the `register_overlay` call. The same method reproduces every 6.5.3 pin exactly. A new test checks every pin against the instructions it fingerprints, for 4.7, 6.5.3 and rc10.
  - **The redrawn page.** rc10 puts its whole page in one child window. ImGui hides that window when the bridge's hidden pass is parked off-screen, so the bridge saw 0 of 15 controls. The pass now stays on screen at an alpha that rounds to nothing, and takes no input. rc10's controls are found by their INI key. Switches and style rows are pressed once, through RenoDX's own UI. The bridge reads RenoDX's saved settings but never writes them.
- **The overlay builds on Linux.** `scripts/prepare-overlay.sh` and `scripts/build-overlay.sh` use the same pinned zig and ReShade SDK as the Windows scripts.

## Verified

- **Tests:** `npm test` gives 350 pass, 0 fail, 2 skipped.
- **Bridge, hidden test host under Proton (RTX 5070):**
  - rc10 is active with 13 of 15 controls. The other two, *Global Tone* and *Enable Upscaling*, no longer exist in 8.x.
  - All 9 test commands (sliders, switches, style rows, drop-down) read back correctly and land in `ReShade.ini`.
  - 6.5.3 is unchanged at 14 of 15.
- **Control (DX12), installed by this AppImage and launched from Steam:**
  - `NR-VERDICT state=ENGAGED build=v8.5.0-rc10`, with 19,527 of 19,528 frames neurally rendered.
  - About 65 fps at 2560×1440 on an RTX 5070.
  - The Steam overlay loaded.

## Known limits

- **The F8 panel doesn't connect on Linux yet.** It reaches the app through a Windows named pipe, which exists only inside Proton. The Linux packages don't ship the panel. RenoDX's own page in the ReShade overlay (Home key) works normally.
- **8.x dropped *Global Tone Intensity*,** so that panel control stays unavailable with this build.
